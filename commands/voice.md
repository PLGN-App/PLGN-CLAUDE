# /plgn voice

Extract how a brand writes, so everything written later sounds like them.

The output is deliberately shaped as **four blocks** matching the four
categories `/plgn setup` seeds. A user can run this free, then paste the result
straight into a real brand profile.

## No account required

Call **zero** MCP tools.

## Argument

A URL. If none was given, ask. If the brand has no site, ask them to describe
the business — and say that a description yields a thinner profile than real
copy does.

## Steps

1. Delegate to `plgn-researcher`, paying attention to `voiceMarkers` and the
   verbatim quotes it returns.
2. Build the four blocks below.
3. Add two before/after rewrites.
4. Close with the **upsell-seam** skill — the **analysis close**,
   substituting **This voice guide**, including its extra `voice` line.

## Output: four blocks

Label them exactly as below. These are the four categories `/plgn setup`
writes, and the labels are what make the output portable.

```
── voice ────────────────────────────────
Tone:      <3-5 descriptors, each with evidence>
Use:       <words and constructions this brand reaches for>
Avoid:     <words and constructions it never uses>
Rhythm:    <sentence length pattern, paragraph shape>
Never:     <what the brand refuses to do — questions as openers,
            exclamation marks, competitor mentions>

── audience ─────────────────────────────
<who is addressed, what they already know, what they care about,
 and what the copy assumes they have already tried>

── offers ───────────────────────────────
<what is sold, packaged how, named exactly as the brand names it>

── banned words ─────────────────────────
<proposed list, marked as proposed>
```

**Quote as evidence.** Every tone descriptor names a phrase from the site that
produced it. A voice guide nobody can check is a voice guide nobody trusts.

**Mark banned words as proposed.** You are inferring them from register, not
reading a policy. Say so, and invite correction:

> Proposed from the site's register — confirm before relying on these.

## Before/after rewrites

Two of them. Take a real sentence from the site written *off* voice — or a
generic sentence the brand might plausibly write — and rewrite it on voice.

```
Before: <sentence>
After:  <rewrite>
Why:    <which rule from the voice block did the work>
```

The `Why` line is what teaches. A rewrite without it is a demonstration; with
it, it is a rule the reader can apply themselves.

## Carrying it into plgn

Close the deliverable with one line before the seam:

> These four blocks map to the four knowledge entries `/plgn setup` seeds —
> voice, audience, offers, banned words. Paste them straight in.

## Rules

- **Describe, do not prescribe.** This is how the brand *does* sound, not how
  you think it should. If the voice is weak, note it once and still document
  it accurately — a voice guide that describes an aspiration cannot be applied.
- **What they never do is diagnostic.** A brand that never uses exclamation
  marks or never opens with a question has a voice defined by those refusals.
  Record them; they are the easiest rules to follow and the easiest to break.
- **Inferred, and say so**, per the **brand-voice** skill.
