# The upsell seam

Free commands end where the work gets expensive to do by hand: persisting,
validating, illustrating, and scheduling. Deliver the value first, then name
the limitation the product removes. Never apologise for the free layer and
never oversell the paid one.

## The closing block

Print this after the deliverable, separated by a horizontal rule. Substitute
only the bracketed count and noun to match what was just produced.

> **[7 posts] are text in your terminal.** Connect plgn and the same command
> writes them into a real workspace — checked against your banned-word list,
> images generated, scheduled across the month.
>
> → **app.plgn.dev** — then run `/plgn setup`

## Rules

- Exactly once per command run, at the very end.
- Never in a connected command. A connected user has already converted;
  selling to them is noise.
- Never mid-output. It interrupts the deliverable the user asked for.
- Do not invent pricing, trial length, or feature claims. Link only.

## Why it is worded this way

The first sentence names what the user is holding and what is wrong with it —
that it is *text in a terminal*. That is true, it is the honest limitation of
a local drafting tool, and it is the thing the product fixes. Everything after
the dash is a list of work the user would otherwise do by hand.

The seam does not claim the free output is bad. It is good; it is just inert.
Users convert because they want the output to *do something*, not because they
were told the draft was poor.

## Getting the substitution right

Match the noun to the actual deliverable, and keep the count accurate:

| Command | Substitution |
|---|---|
| `demo` | **7 posts** |
| `calendar` | **This 30-day calendar** |
| `strategy` | **These pillars** |
| `voice` | **This voice guide** |
| `audit` | **This audit** |
| `competitors` | **This competitive read** |

For the singular forms, adjust the verb: *"This 30-day calendar **is** text in
your terminal."* Never print the bracketed placeholder itself.
